## The idea

Vibe coding changed the starting point for software: you describe what you want, an agent
drafts it, you run it and improve it. The first draft is no longer the hardest part.

**Vibe manufacturing** is the next frontier — *intent-led, agent-assisted creation of physical
products.* The difference is that in the physical world, undo is a reprint, a re-order or a
redesign. MyriadFlow exists to close that gap.

Three things changed at once, and together they make it possible now:

- **Agents got hands.** They don't just suggest code; they build, flash a board, read the
  serial log and try again.
- **Chips got capable.** A thumb-sized board with Wi-Fi and Bluetooth is an everyday,
  low-cost part.
- **Factories got upload buttons.** Upload a file, get a quote, receive parts — printing,
  PCBs, CNC and assembly run as services.

The result is a world where products no longer have to be one design for a million people.
A product can start from one person's hands, desk, colour and problem — and still be made
properly.

## What MyriadFlow is

A platform where anyone with a hardware idea can develop a prototype, show it to a community,
raise support for a production run, and bring the finished product to buyers. The creator
might be an engineer, a designer, a student, or someone who knows the problem but has never
opened a CAD tool.

- **Myriad** — the breadth of ideas and people: wearables, assistive devices, home objects,
  robotics, tools, climate hardware, furniture, and categories no one has named yet.
- **Flow** — the connected journey that carries each idea through brief, proof, backing,
  production and launch.

**The promise:** Describe it. Shape it. Prove it. Back it. Make it. Ship it.

## The creator journey

| Step | What the creator sees | What it leaves behind |
|---|---|---|
| 01 Start | Describe an idea; attach a sketch, photo or existing STEP file. | Project brief, open questions, intended user. |
| 02 Shape | Compare product approaches and choose a first testable form. | Versioned requirements and a prototype plan. |
| 03 Build | Review a model, materials, feasibility checks, costs and a prototype job. | CAD files, BOM, estimates, build record. |
| 04 Learn | Handle the prototype, record what worked, invite feedback, revise. | Test evidence, changes, updated design and risk list. |
| 05 Launch | Publish the story, funding goal, milestones and the offer to supporters. | Public project page and campaign plan. |
| 06 Fulfill | Confirm demand; coordinate suppliers, a pilot run, production and shipping. | Production status, orders and creator updates. |

### The prototype loop

The first working loop is deliberately narrow:

```
brief → PartSpec → parametric CAD → DFM checks → manufacturing plan → slice → print → PrintReport → revision
```

A **PartSpec** holds geometry, fit, material and functional intent. A **ManufacturingPlan**
describes how a particular machine and material should build it. Every physical test produces
a **PrintReport** the next revision can use. Printers and suppliers plug in as structured
capabilities; actual price, quality and schedule come from real quotes and tests.

### Agents with clear boundaries

TVASTR asks clarifying questions, drafts specs, generates parametric parts, checks geometry and
materials, prepares jobs, observes results and proposes revisions. **Humans approve** designs,
spending, machine starts, production commitments, campaign terms and major changes. Every
project states what is verified, what is estimated, and what still needs testing.

## The launchpad

A project page shows the promise, the prototype, the remaining risks and the path to delivery —
so supporters back evidence, not renders.

| State | Evidence shown | Community action |
|---|---|---|
| Idea | Problem, intended user, concept, creator. | Follow, comment, join a waitlist. |
| Prototype | Working demo, photos, test notes, revisions. | Give feedback, request a pilot unit. |
| Campaign | Funding goal, unit economics, timeline, risks. | Back the project. |
| Pilot run | Supplier quotes, design freeze, sample checks. | Track milestones, receive updates. |
| Product | Availability, delivery and support. | Order, review, recommend. |

Funding is a configurable launch tool, not a default: preorders, reservations, rewards or
community backing. Before a campaign opens, the creator states the minimum viable batch,
per-unit cost, tooling and test needs, contingency and timing — and what happens if a goal is
missed or a prototype fails.

**The flywheel:** more ideas bring more builders; visible prototypes bring better feedback;
better evidence helps supporters judge a launch; finished products build trust and reusable
manufacturing knowledge for the next wave of creators.

## Also in the flow: music and phygital art

The flow that ships a desk object can ship a pressing, a print or a sculpture. Musicians and
artists use MyriadFlow to design and produce physical editions — each paired with a digital
companion that carries its edition, signature, process log and story.

## Execution

The long-range destination is a launchpad for hardware ideas of every kind. The first build
proves one complete path through the hard middle.

| Phase | Deliverable | Proof of success |
|---|---|---|
| A · Compile | PartSpec → valid parametric enclosure → STEP/STL preview. | Dimensions and features survive revisions. |
| B · Make | Manufacturing plan, DFM, slicing, reference printer connection. | A real enclosure prints with the right material and profile. |
| C · Learn | Job status, PrintReport, test notes, guided redesign. | Failure or feedback leads to a traceable, improved part. |
| D · Share | Creator workspace, project page, waitlist, updates. | A visitor understands the proof and what remains. |
| E · Launch | Campaign configuration, milestones, supporter tracking. | A vetted pilot run with explicit terms and progress. |
| F · Scale | Supplier handoff, production QA, orders and fulfilment. | A completed batch reaches buyers with visible status. |

**Early boundaries.** Prove an enclosure before arbitrary assemblies. Production electronics,
certification, tooling and high-volume manufacturing go through specialist review and partner
processes. A first print is never presented as proof that a device is safe, certified or
production-ready.
